# Dynamic Pro ERP — نظام الإدارة المتكامل

نظام ERP متكامل للعقارات والمقاولات وإدارة الشركات: محاسبة، مخازن، موظفون، أصول، مبيعات، مشتريات، تأجير، تصنيع، CRM، واجهة موبايل (PWA) وتقارير PDF.

---

## المتطلبات

- **Windows** 10/11
- **Python 3.12+** (مطابق لإصدارات الإنتاج الحالية)
- **PostgreSQL** للنشر السحابي

### إعداد قاعدة البيانات

أنشئ قاعدة البيانات والمستخدم في PostgreSQL باستخدام بيانات اعتماد قوية من إدارة الأسرار لديك، ثم اضبط متغيرات البيئة المناسبة:

```sql
CREATE USER <db_user> WITH PASSWORD '<كلمة مرور قوية>';
CREATE DATABASE <db_name> OWNER <db_user>;
```

المتغيرات الأساسية: `DB_USER`، `DB_PASSWORD`، `DB_HOST`، `DB_PORT`، `DB_NAME`.

> **أمان:** لا توجد بيانات اعتماد افتراضية منشورة في المستودع. في بيئة الإنتاج يجب توفير `SECRET_KEY` وبيانات قاعدة البيانات وRedis من مدير أسرار موثوق، وعدم وضعها داخل Git. يمكن استخدام `DYNAMICPRO_BOOTSTRAP_ADMIN_PASSWORD` أثناء التهيئة الأولى فقط، ثم إزالته.

## التشغيل

### مباشر من الكود

```bat
start.bat
```

أو:

```bat
pip install -r requirements.txt
python app.py
```

ثم افتح:

- على نفس الجهاز: `http://localhost:5000`
- على الشبكة: `http://<عنوان-الجهاز>:5000`

### نافذة سطح المكتب (pywebview)

```bat
python desktop.py
python desktop.py --background   :: خادم فقط بدون نافذة
python desktop.py --dev          :: خادم مع نافذة كونسول
```

### تسجيل الدخول

لا توجد كلمة مرور افتراضية ثابتة للمدير.

في بيئة الإنتاج السحابية يجب ضبط `DYNAMICPRO_BOOTSTRAP_ADMIN_PASSWORD` بكلمة مرور قوية من مصدر أسرار خارجي عند التهيئة الأولى، مع تفعيل 2FA لحساب Control Center، ثم إزالة سر التهيئة بعد إنشاء الحساب.

## قاعدة البيانات والترحيلات

يستخدم المشروع Alembic لإدارة مخطط PostgreSQL. الترتيب الحالي يبدأ من `0000_initial_schema` ثم الترحيلات اللاحقة حتى `0005_financial_year_integrity`.

قبل نشر إصدار جديد:

```bat
alembic upgrade head
```

ولا يجب تعديل migration تاريخية بعد نشرها؛ أضف migration جديدة لكل تغيير لاحق.

في النشر السحابي يجب تطبيق migrations قبل تشغيل workers، ولا تستخدم `db.create_all()` كآلية لنشر تغييرات schema.

## HTTPS والموقع الجغرافي (GPS) من الموبايل

المتصفحات الحديثة تتطلب secure context لاستخدام Geolocation الكامل. لتشغيل GPS الحقيقي من الهاتف:

1. ولّد شهادة مناسبة من خلال:

   ```bat
   python scripts\\generate_ssl_cert.py
   ```

2. فعّل HTTPS من إعدادات الخادم.
3. افتح:

   ```text
   https://<عنوان-الجهاز>:5443/mobile
   ```

> للاستخدام التجاري الخارجي يجب استخدام شهادة TLS موثوقة، وليس شهادة ذاتية التوقيع.

| الملف | الغرض |
|---|---|
| `app.py` | إنشاء التطبيق وتسجيل الوحدات وتشغيل الخادم |
| `config.py` | إعدادات قاعدة البيانات والأسرار ووضع التشغيل |

| `models/` | نماذج البيانات لكل وحدة |
| `routes/` | واجهات البرمجة وصفحات الوحدات |
| `templates/` + `static/` | الواجهة التقليدية RTL عربي/إنجليزي |
| `frontend/` | الواجهة الحديثة المبنية على Next.js |
| `licensing/` | الترخيص وإدارة الشركات والاشتراكات وقواعد البيانات |

| `audit/` | سجل التدقيق |
| `deployment/` | إعدادات النشر وNginx |
| `Dockerfile` | صورة الإنتاج للحاويات |
| `desktop.py` | نافذة سطح المكتب |
| `build.bat` / `build_installer.bat` | بناء النسخة المجمّدة وملف التثبيت |

## ERP Control Center

تُدار من `/admin/` وهي منطقة الإدارة المركزية للمنصة، منفصلة عن بيئة شركة العميل.

- إدارة الشركات وقواعد البيانات.
- الخطط والتجارب والاشتراكات والتراخيص.
- المستخدمون والأدوار والصلاحيات.
- الأمان و2FA والجلسات وسجل الأحداث.
- التقارير والفوترة والتحليلات.

## اختبارات الجودة

يحتوي خط CI على فحوصات المصدر، lint، compilation، تدقيق الحزم، اختبارات backend، تحقق من سلسلة Alembic، اختبار ترحيل قاعدة بيانات فارغة، smoke tests للتطبيق، وفحوصات frontend وDocker ونسخة Windows، إضافة إلى حواجز أمنية للإنتاج.

لا يُعتبر الإصدار جاهزًا تجاريًا لمجرد نجاح unit tests؛ يجب أيضًا اجتياز ترحيلات قاعدة البيانات، العزل الأمني، اختبارات الاسترجاع والنسخ الاحتياطي، وفحوصات artifacts النهائية، مع نجاح بوابات CI/CD الفعلية.

## التطوير

- يمكن تشغيل بيئة التطوير محليًا عبر `python app.py`.
- ترجمة الواجهة في `i18n.py` لمفاتيح `ar` و`en`.
- لا تضع أسرار الإنتاج أو بيانات العملاء داخل المستودع.
- استخدم migration جديدة بدل تعديل migrations منشورة سابقًا.
